# UCP Shopping Tech Council (STC) Meeting - 2026-07-17

## 1. General Topics

- **Topic:** Governance and Domain Technical Council Restructuring
  - **Notes:** Amit Handa announced several official governance updates, including the formal renaming of the Technical Council (TC) to the Domain Technical Council (DTC). The shopping domain will now operate under its own dedicated DTC. Furthermore, the charter for the Food Ordering DTC has been finalized, and a payments DTC charter has been submitted as a joint collaboration to coordinate future payments roadmap discussions.

## 2. Open Discussions & DTC PR Reviews

- **Topic:** Refund Policy Implementation Sequencing
  - **Notes:** Evaluated how to model and represent complex merchant refund policies and return rules within the core schemas. Agreed a two-step implementation strategy, establishing a base policy shape first before defining more granular refund and return structures.
  - **Context:** [257 feat: add return policy extension](https://github.com/Universal-Commerce-Protocol/ucp/pull/257)
- **Topic:** Base Payment Authentication Actions
  - **Notes:** Reviewed the base PR for payment authentication actions to establish a consistent framework for initiating multi-step transactional flows.
  - **Context:** [458 feat: Add Payment Authentication Actions](https://github.com/Universal-Commerce-Protocol/ucp/pull/458)
- **Topic:** Payment Terms and Deferred Payments
  - **Notes:** Daniel Wyckoff presented an update on the payment terms RFC, focusing on deferred payment use cases (such as lodging and bookings) where a deposit is captured upfront and the remaining balance is collected at checkout. This also covers multi-tender and split payment interactions. Two draft schemas have been opened.
  - **Context:** [602 feat: Add Payment Terms with Well-Defined Schedules](https://github.com/Universal-Commerce-Protocol/ucp/pull/602)
  - **Context:** [603 feat: Add Payment Terms with Simple Schedules](https://github.com/Universal-Commerce-Protocol/ucp/pull/603)
- **Topic:** Additional Fields and Runtime Customization
  - **Notes:** Debated a pull request allowing businesses to pass unstructured custom fields (such as gift engraving notes or birthday details) to be rendered by the consumer platform. Amit Handa expressed concern that rendering arbitrary runtime UI widgets is an anti-pattern and suggested leveraging the existing messages construct or structured extensions instead. Vic Duggan agreed to share a prototype to demonstrate the UI behavior.
  - **Context:** [481 feat: Add additional fields proposal (from Shopify)](https://github.com/Universal-Commerce-Protocol/ucp/pull/481)
- **Topic:** Locations Capability PR Refinements
  - **Notes:** The team reviewed the design of the locations capability, touching on multiple facets:
    - _Service Structure:_ Discussed whether the location endpoints should reside in a common namespace or a capability-specific one, aligning on advertising common capabilities as a shared service.
    - _Geofencing:_ Challenged the restriction of geofences to simple circular radii, agreeing that a flexible design is needed to support polygon-based modeling in the future.
    - _Schedule Modeling:_ Aligned on cross-referencing and adopting the schema.org standard contract for location opening hours rather than defining a duplicate parallel structure.
    - _Inventory & Amenities:_ Agreed on enforcing strict semantics regarding availability to prevent explicit inventory disclosure, and decided to rely on recommended common amenity strings rather than trying to define an exhaustive vertical list.
  - **Context:** [545 feat: Introduce Location Search + Lookup capabilities](https://github.com/Universal-Commerce-Protocol/ucp/pull/545)
- **Topic:** Generic Request Constraints
  - **Notes:** Daniel Wyckoff and Ilya Grigorik discussed evolving the constraints pattern. Rather than applying a "mix-in" pattern to individual schemas, the team is moving toward a well-defined, single constraint entity that can be applied universally across the protocol.
  - **Context:** [424 feat: structured constraints for instruments and beyond](https://github.com/Universal-Commerce-Protocol/ucp/pull/424)
- **Topic:** Protocol and Capability Versioning Release Strategy
  - **Notes:** Discussed the trade-offs of independent, capability-level versioning versus protocol-wide version cuts, focusing on integrator overhead and schema parsing correctness.
  - **Context:** [499 RFC: Refactor of codebase to support capability versioning independent of protocol version](https://github.com/Universal-Commerce-Protocol/ucp/pull/499)
