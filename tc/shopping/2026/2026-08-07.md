# UCP Shopping Tech Council (STC) Meeting - 2026-08-07

## Attendance

- **Present:** Demian Raspall, Amit Handa, Drew Olson, Greg Smith , Caroline George, Ilya Grigorik, Daniel Wyckoff, James Andersen, Maxime Najim, Prasad Wangikar, Scot DeDeo, Imran Hoosain, Uddhav Kambli, Niranjan Manjunath

## 1. General Topics

- **Topic:** Feeds Domain Working Group Nomination Process and Charter
  - **Discussion:** James Andersen and Greg Smith discussed establishing the Feeds Domain Working Group (DWG) to address bulk product discovery and product feed standards. Amit Handa confirmed that the Governing Council (GC) has formally approved the Feeds DWG charter. To gather interest, a standardized Google Form template will be used to collect nominations.
  - **Context:** [Feeds DWG Charter](https://github.com/Universal-Commerce-Protocol/ucp/issues/682)
- **Topic:** Quality-First Release Schedule Strategy for Version 8 (V8)
  - **Discussion:** The council reviewed the timeline for the upcoming V8 release, originally targeted for August 14th. Given the significant volume of outstanding payments, locations, and groceries pull requests, Amit Handa proposed maintaining the August 14th target but establishing flexibility to push the release to August 21st if additional time is needed to resolve technical comments and ensure the highest quality.
- **Topic:** SDK and Code Generation Strategy (RFC #484)
  - **Notes:** Greg Smith has taken over the RFC for the UCP Open Source Unified Toolchain and SDK Generation and plans to split it into two distinct parts: SDK Generation and Conformance Testing. Statically typed language SDKs are experiencing issues because certain JSON Schema vocabulary patterns do not play well with automatic code generators. Greg plans to statically enforce stricter schema patterns. While these changes cannot be fully implemented for the V8 release, the group prioritized this as a major priority for the next release cycle to ensure that future SDKs are released in lockstep with new protocol versions.
  - **Context:** [Proposal: UCP Open Source Unified Toolchain and SDK Generation](https://github.com/Universal-Commerce-Protocol/ucp/issues/484), [refactor!: migrate totals.json from array to object schema](https://github.com/Universal-Commerce-Protocol/ucp/pull/684)

## 2. Open Discussions & PR Reviews

- **Topic:** Media Extension Proposal (Richer Media Support)
  - **Notes:** Ilya Grigorik proposed a new, backwards-compatible media extension for the catalog capability to support richer media formats (such as 3D models and videos), whereas the current specification only exposes a single image. While this extension is not on the critical path for the V8 release, the group agreed to review the proposal as a valuable enhancement.
  - **Context:** [feat(media): model image, video, and 3D variants](https://github.com/Universal-Commerce-Protocol/ucp/pull/690)
- **Topic:** Groceries Roadmap and Planning (PR #597 / PR #653)
  - **Notes:** The groceries PR covering fractional quantities and location context is progressing. To meet the V8 timeline, the initial scope will be kept small. Amit Handa requested that business-side participants review and provide LGTMs on the design patterns. TC agreed that further deep dives are required to address fulfillment logic and location validation, as the current could lead to some incorrect behavior. This will be addressed in a series of upcoming working sessions.
  - **Context:** [feat!: Support fractional quantities and unit measurement in lower funnel capabilities](https://github.com/Universal-Commerce-Protocol/ucp/pull/597) / [feat!: define sale-basis steps for quantities](https://github.com/Universal-Commerce-Protocol/ucp/pull/653)
- **Topic:** Payment Schedules and Terms (PR #602 / PR #603 / PR #692)
  - **Notes:** Daniel Wyckoff and Ilya Grigorik debated the design direction for payment terms and schedules. The discussion focused on whether payment terms should be modeled as a reference nested inside a payment instrument or as a separate schedule. Daniel Wyckoff raised concerns that nesting the schedules too closely inside the payment instrument might reduce flexibility when a transaction involves multiple payment methods. The team agreed to merge/compress these conflicting PRs into a single cohesive design direction, which will be the focus of a deep dive session.
  - **Context:** [RFC: Payment terms and scheduled payments](https://github.com/Universal-Commerce-Protocol/ucp/issues/587), [feat: Add Payment Terms with Well-Defined Schedules](https://github.com/Universal-Commerce-Protocol/ucp/pull/602), [feat: Add Payment Terms with Simple Schedules](https://github.com/Universal-Commerce-Protocol/ucp/pull/603), [negotiate payment terms as a checkout selection](https://github.com/Universal-Commerce-Protocol/ucp/pull/692)
- **Topic:** Request Constraints Pattern (PR #424)
  - **Notes:** Daniel Wyckoff and Ilya Grigorik debated the request constraints proposal, focusing on the architectural tension between a "mixing" pattern (PR #424) versus a top-level UCP namespace (PR #655). They acknowledged the difficulty of expressing domain-specific constraints (such as card brand restrictions) within a generic protocol structure. A deep dive session will be scheduled next week to resolve this architectural tension, with Greg Smith contributing SDK-related perspectives.
  - **Context:** [feat: structured constraints for instruments and beyond](https://github.com/Universal-Commerce-Protocol/ucp/pull/424), [feat: add response-carried request constraints](https://github.com/Universal-Commerce-Protocol/ucp/pull/655)
