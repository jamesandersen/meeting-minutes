## Attendance

## 1. General Topics

- **Topic:** Version 8 (V8) Launch Timeline
  - **Discussion:** Ilya Grigorik proposed setting a mid-August timeline for the V8 launch to drive pressure testing. The group aligned on targeting mid-August for the official V8 release and agreed to schedule high-frequency deep dives to resolve remaining blocking PRs.
- **Topic:** Protocol Backporting Strategy and Policy for Version 8 (V8)
  - **Discussion:** The group discussed the strategy for cherry-picking and backporting changes to the V8 branch. Jing Li introduced a proposal indicating that recent refactoring into a common directory should minimize the need for manual backports. However, strategically sensitive features might require "impure" backports involving manual file path updates. Anurag Sinha emphasized that the manual effort is highly justified given the significant benefit to integration partners currently operating on the stable V48 release. The team formalized a general backporting policy to default to backporting all clean, backwards-compatible changes, while reviewing non-clean merges on a case-by-case basis. Ilya Grigorik proposed utilizing an automated assistant model to analyze merge conflicts and estimate development effort for non-clean backports to reduce the release management burden.
- **Topic:** UCP Schema Evaluation with AI Models
  - **Notes:** Anurag Sinha shared findings from testing how generative AI models interact with UCP schemas. Evals indicate that models resolve instructions and execute tool calls much more accurately when schemas are flat rather than deeply nested. Amit Handa supported attaching evaluation results to PRs, emphasizing that schemas are primarily consumed by machines and agents, making agent-friendliness a key design criterion. Jing Li and Ilya Grigorik discussed ensuring that tool descriptions published on ucp.dev are agent-friendly. Ilya noted that the UCP CLI tool uses specific call-to-action suggestions to guide agents through commerce journeys. The group agreed to collaborate on developing generic guidance for flat, agent-friendly schema designs.

## 2. Open Discussions & DTC PR Reviews

- **Topic:** Capability Advertisement Structure Alignment
  - **Discussion:** The team discussed the directory structure for service advertisements. Ilya Grigorik and Jing Li aligned on how the protocol should expose locations and other shared capabilities. The group agreed that the preferred path forward is to advertise "common" as a top-level service and break down individual capabilities at the common capability level, rather than using nested directories.
  - **Context:** [Locations service structure and namespaces](https://github.com/Universal-Commerce-Protocol/ucp/pull/589)
- **Topic:** Capability Versioning and Release Cadence
  - **Discussion:** Jing Li clarified that the previous RFC on capability-level versioning will be deprecated by a new PR regarding version release. The group debated the complexity of managing payloads across mixed capability versions in production environments.
  - **Context:** [PR 614: Version Release Strategy](https://github.com/Universal-Commerce-Protocol/ucp/pull/614)
- **Topic:** Location Hints and Geofencing (PR 589)
  - **Notes:** Jing Li is addressing comments from Ilya Grigorik and Amit Handa. The geofencing design will be simplified to circular radii for the initial V8 release, with a plan to support more complex polygons in the future. Schedule modeling will align with standard specifications. Ilya cautioned against inventory harvesting and recommended strict access control over real-time location details.
  - **Context:** [feat!: Introduce Location Search + Lookup capabilities](https://github.com/Universal-Commerce-Protocol/ucp/pull/589)
- **Topic:** 3D Secure (3DS) Integration and Base Actions (PR 458 / PR 553)
